## CATEGORY DEFINITIONS & STRICT DETECTION RULES

### reentrancy  (SWC-107)
External contract calls allow re-entry before state is updated (checks-effects-interactions violated).
ONLY report if ALL five conditions hold simultaneously:
  1. External call to `msg.sender` OR an untrusted address (NOT a fixed trusted address like a known oracle or an immutable owner)
  2. The call uses `.call{value:…}()` — NOT `.transfer()` or `.send()` (those are gas-limited, safe in 0.8+)
  3. A security-critical state variable (balance, allowance, ownership) is updated AFTER the call, not before
  4. There exists a callable public/external function that can be invoked during the external call
  5. No reentrancy guard is present (`require(!locked)`, OpenZeppelin ReentrancyGuard, etc.)
DO NOT report if: state is updated before the call | call is to a fixed trusted address | `.transfer()` is used | a guard is present.

### access_control  (SWC-105/106/115)
Missing or bypassable authorisation on critical functions.
Report patterns: unprotected `withdraw`/`mint`/`pause`/`upgrade` functions; `initialize()` callable multiple times; use of `tx.origin` for auth; unprotected `selfdestruct`/`suicide`; `delegatecall` to user-controlled address.
DO NOT report if the function is intentionally public and non-sensitive.

### arithmetic  (SWC-101)
Integer overflow/underflow or unsafe math.
STRICT VERSION RULE:
  - pragma >= 0.8.0 → DO NOT report overflow/underflow UNLESS inside an explicit `unchecked {}` block
  - pragma < 0.8.0 → report ONLY if arithmetic is unprotected (no SafeMath, no prior require check)
DO NOT report: simple assignments, operations on constants, divisions by zero without context, subtraction with an explicit zero-check.

### unchecked_low_level_calls  (SWC-104)
Return value of `.call()`, `.send()`, `.transfer()`, or ERC-20 `transfer`/`transferFrom` is not checked.
Report ONLY the exact line where the return value is silently ignored.
Two subtypes: (A) external call return ignored, (B) ERC-20 token transfer return ignored.

### denial_of_service  (SWC-113/128)
Gas exhaustion through unbounded loops, forced ETH push to an address that can revert, or logic that can be permanently bricked.
Report only genuine blocking patterns, not theoretical gas concerns.

### front_running  (SWC-114)
Logic whose outcome depends on transaction ordering, mempool visibility, or miner-controlled sequencing (MEV).
Patterns: first-caller wins, commit-reveal without time-lock, swap price based on pending state, rewards tied to tx arrival order.
DO NOT report deterministic logic that is independent of ordering.

### time_manipulation  (SWC-116)
`block.timestamp` (or `now`) used for critical decisions: random number generation, exact access-time gates, or pricing.
Report ONLY when the timestamp is used as the primary controlling factor and a miner could gain by manipulating it by ±15 seconds.
DO NOT report: timestamp used only for logging, or where a ±15s drift has no exploitable effect.

### bad_randomness  (SWC-120)
Predictable or miner-manipulable source used for randomness or outcome selection.
Report ANY of: `block.timestamp`, `block.number`, `block.difficulty` / `block.prevrandao`, `blockhash()`, private seed derived from block data, or `keccak256(abi.encodePacked(block.*, msg.sender))` used for game/lottery decisions.
DO NOT report if Chainlink VRF or a verified randomness oracle is used.

### short_addresses
EVM payload padding from short address inputs causes argument shift.
Report only contracts that accept raw address inputs without length validation.

### other
Use ONLY when a finding is clearly exploitable but does not fit any of the above nine categories.
If you are not sure whether it is exploitable, do NOT report it.
